# 自动历史与数据恢复

自动历史从使用包含此功能的构建后开始产生，无法追溯安装前已经被覆盖的内容。不修改现有 JSON 数据格式，不迁移原始数据。

## 何时保存

- 保存变化的便签、日期记录、版块配置或元数据时，先保存原文件，再保存新内容，然后原子替换原文件。
- 删除便签或日期记录前保存原文件；便签删除的索引和正文一起处理，删除失败时恢复索引。
- 相同内容不会增加版本；便签仅修改 `updatedAt` 或 JSON 排版、键顺序变化时不增加内容版本。
- 空闲时不扫描、不定时复制全部数据；文件写入按顺序执行，防止并发保存竞争临时文件。
- 检查点写入失败、历史损坏或容量不足时阻止覆盖/删除，保留原文件并报告保存失败。便签的待保存内容会保留以便重试。
- 关闭窗口前等待待保存数据；保存失败则取消退出，不再超时强制关闭。日期记录保存失败时保留编辑并阻止切换日期。

## 空间与保留规则

内容压缩存入数据目录的 `backups/automatic/blobs/`，相同内容共用一个文件。`backups/automatic/index.json` 记录文件路径、版本时间和内容校验值。

每个文件保留最近 20 个版本、近 24 小时内每小时一个代表版本、近 30 天内每天一个代表版本。重叠版本只保留一次。压缩内容合计最多 200 MiB；达到上限后优先移除较旧版本，同时保留各文件最新两个版本，防止覆盖前的版本刚保存就被清理。无法满足容量限制时保存失败，原文件不变。索引本身的少量空间不计入该内容上限。

## 如何恢复

1. 打开便签的“历史”，预览该便签的正文，选择“恢复为新便签”。原便签保留，恢复副本有新的 ID。
2. 删除的便签可从“设置 → 查看自动历史”按原标题搜索，然后恢复为新便签。
3. 日期记录、版块配置和元数据可在设置的自动历史中单独恢复。先确认目标路径与预览内容；恢复前保存当前编辑并建立检查点，恢复后重新加载应用。
4. 不直接恢复便签索引，应逐条恢复便签，避免遗漏、覆盖或重新关联错误的文档。

自动历史保留在当前数据目录内；更换数据目录不会自动迁移历史。现有手动 ZIP 备份/导出仍只包含当前数据，不重复打包 `backups/` 里的自动历史。需要迁移历史时，连同整个数据目录一起复制。自动历史用于误操作恢复，不能替代保存在另一磁盘的灾难恢复备份。

## 撤销行为

`Ctrl+Z` / `Ctrl+Shift+Z` 只撤销/重做当前文档会话中的编辑。切换便签、删除后选择其他便签、加载另一个日期或加载恢复内容时重建编辑器状态，清除上一份文档的撤销与重做记录。同一文档的普通编辑和光标位置保留原有行为。

删除尚未提交时点击另一条便签，会等删除完成再应用这次选择，避免删除回调覆盖刚点击的便签。
