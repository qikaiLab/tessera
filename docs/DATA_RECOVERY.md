# 自动历史与数据恢复

自动历史从使用包含此功能的构建后开始产生，无法追溯安装前已经被覆盖的内容。不修改现有 JSON 数据格式，不迁移原始数据。

## 何时保存

- 保存变化的便签、日期记录、版块配置或元数据时，先保存原文件，再保存新内容，然后原子替换原文件。
- 删除便签或日期记录前保存原文件；便签删除的索引和正文一起处理，删除失败时恢复索引。
- 相同内容不会增加版本；便签仅修改 `updatedAt` 或 JSON 排版、键顺序变化时不增加内容版本。
- 空闲时不扫描、不定时复制全部数据；文件写入按顺序执行，防止并发保存竞争临时文件。
- 检查点写入失败、历史损坏或容量不足时阻止覆盖/删除，保留原文件并报告保存失败。便签的待保存内容会保留以便重试。
- 关闭窗口前等待待保存数据；保存失败则取消退出，不再超时强制关闭。日期记录保存失败时保留编辑并阻止切换日期。

## 空间与保留规则

内容压缩存入数据目录的 `backups/automatic/blobs/`，相同内容共用一个文件。`backups/automatic/index.json` 记录文件路径、版本时间和内容校验值。

每个文件保留最近 20 个版本、近 24 小时内每小时一个代表版本、近 30 天内每天一个代表版本。重叠版本只保留一次。压缩内容合计最多 200 MiB；达到上限后优先移除较旧版本，同时保留各文件最新两个版本，防止覆盖前的版本刚保存就被清理。无法满足容量限制时保存失败，原文件不变。索引本身的少量空间不计入该内容上限。

## 如何恢复

1. 打开便签的“历史”，预览该便签的正文，选择“恢复为新便签”。原便签保留，恢复副本有新的 ID。
2. 删除的便签可从“设置 → 查看自动历史”按原标题搜索，然后恢复为新便签。
3. 日期记录、版块配置和元数据可在设置的自动历史中单独恢复。先确认目标路径与预览内容；恢复前保存当前编辑并建立检查点，恢复后重新加载应用。
4. 不直接恢复便签索引，应逐条恢复便签，避免遗漏、覆盖或重新关联错误的文档。

自动历史保留在当前数据目录内，随「更改目录」一起复制到新目录（见下节）。现有手动 ZIP 备份/导出仍只包含当前数据，不重复打包 `backups/` 里的自动历史。自动历史用于误操作恢复，不能替代保存在另一磁盘的灾难恢复备份。

## 更改数据目录

在「设置 → 数据与备份 → 更改目录」选择新文件夹后，软件**不会立刻切换**，只会记下这次请求（`config.json` 的 `pendingDataDirChange`）。真正的迁移发生在**下次启动、打开任何数据之前**：

1. 新文件夹必须是空文件夹（或上次未完成复制留下的、带 `.mototrace-migration-incomplete` 标记的文件夹）；里面有其他文件、位于当前数据目录之内或包含它，都会被拒绝。
2. 把整个数据目录（含 `backups/` 与自动历史）复制过去。每个文件先写成临时名再改名，复制全程目标里带有未完成标记。
3. 逐个文件核对大小和 SHA-256；全部一致才去掉标记，并把新位置写入配置。
4. **旧目录不会被删除或修改**，核对出现任何差异都留在旧目录继续使用，并在启动后提示原因。确认新位置一切正常后，可自行清理旧目录。

如果选的是**已有 MotoTrace 数据**的文件夹，则直接改用它，不复制、不合并，旧目录同样保留，之后可以再切换回去。

已保存的数据目录**不存在**（例如移动硬盘没接上、文件夹被改名或删除）时，软件不会自动新建一个空文件夹顶替，而是弹窗说明，并让你退出或选择另一个文件夹；退出时不改动任何配置，接回磁盘后重新启动即可。

## 撤销行为

`Ctrl+Z` / `Ctrl+Shift+Z` 只撤销/重做当前文档会话中的编辑。切换便签、删除后选择其他便签、加载另一个日期或加载恢复内容时重建编辑器状态，清除上一份文档的撤销与重做记录。同一文档的普通编辑和光标位置保留原有行为。

删除尚未提交时点击另一条便签，会等删除完成再应用这次选择，避免删除回调覆盖刚点击的便签。

## 异常退出后的临时文件

写入时先生成同目录的 `.tmp` 文件，写完并落盘后才替换原文件，所以异常退出后残留的 `.tmp` 要么是完整的新内容，要么是只写了一半。再次启动时，软件会提示“发现未保存的数据”：

- **恢复数据**：内容是完整 JSON 的临时文件会替换原文件（替换前原文件先存入自动历史）。内容不完整（无法解析）的临时文件**不会**覆盖原文件，而是改名为 `.incomplete` 保留在原位置，原文件保持不变；之后不再提示。需要时可手动查看这些 `.incomplete` 文件。
- **丢弃**：只删除这些临时文件，不动原文件。

## 导入与备份的保护

- 导入 ZIP 前先检查压缩包里的每个文件：任何一个不是合法 JSON，或路径试图离开数据目录，就**整体拒绝，不写入任何文件**。
- 备份和导出读取数据目录时，任何文件夹或文件读取失败都会让这次备份失败并提示，而不是生成缺少数据的“成功”备份。
- 导出和导入只接受用户刚在系统对话框里选择的路径，且每次选择只能用一次。
